# AGENTS.md

## 기본 규칙

- 항상 한국어 존댓말로 정중하고 실무적으로 답변합니다.
- 설명은 목록과 짧은 문단으로 명확하게 작성합니다.
- Unity 프로젝트 루트는 `Hyper_Unity/`입니다.
- 기준 환경은 Unity `6000.3.5f2`, URP 2D, Input System `1.17.0`입니다.

## 작업 원칙과 스킬

- 코드 구현·수정·리뷰·리팩터링에는 작업 성격에 맞게 `$karpathy-guidelines`와 `$ponytail`을 적용합니다.
- 요청, 기존 코드, 씬 구조와 완료 조건을 먼저 확인하고 가장 작은 완전한 변경만 수행합니다.
- 기존 에셋, 프리팹, 컴포넌트, Unity 기본 기능과 설치 패키지를 새 구현보다 우선합니다.
- 확인하지 않은 오브젝트, 컴포넌트, 태그, 레이어와 입력 액션을 추측하지 않습니다.
- 사용자 변경과 무관한 파일을 수정하거나 되돌리지 않으며, 미래 대비용 구조와 의존성을 미리 추가하지 않습니다.

## Unity 제작 방식

- `new GameObject`, 런타임 `AddComponent`, 코드 기반 UI·계층 조립 등 오브젝트를 코드로 동적 구성하는 방식을 사용하지 않습니다.
- 동적 생성은 완성된 Prefab을 직렬화 참조하여 인스턴스화하는 방식으로만 구현합니다.
- 고정 오브젝트와 초기 구조는 씬 또는 Prefab에 미리 배치하고 Inspector 참조로 연결합니다.
- 반복되는 오브젝트는 Prefab으로 관리하고 불필요한 Prefab override를 만들지 않습니다.
- 기능, 로딩 경계 또는 협업 단위가 실제로 분리될 필요가 있으면 씬을 나누고 전환·Additive 로딩 책임을 명확히 합니다.
- 반복 조정되는 설정, 밸런스와 콘텐츠 값은 필요할 때 ScriptableObject 또는 직렬화 데이터로 분리하며, 일회성 값까지 과도하게 데이터화하지 않습니다.

## 코드와 구조

- SOLID 원칙을 따르며, 특히 단일 책임 원칙에 따라 각 클래스의 역할을 한 문장으로 설명할 수 있게 구분합니다.
- 입력, 게임 규칙·상태, 표현, 저장·데이터처럼 책임·수명주기·변경 이유가 다른 영역은 명확한 클래스로 분리합니다.
- SOLID를 이유로 구현 하나뿐인 인터페이스, 불필요한 팩토리나 계층을 만들지 않습니다.
- 스크립트 파일명과 주요 타입명을 일치시키고 한 파일에는 하나의 주요 타입을 둡니다.
- Inspector 참조는 public 필드보다 `[SerializeField] private`를 우선하며 필수 참조 누락을 명확히 검증합니다.
- 이벤트 구독과 해제는 `OnEnable`과 `OnDisable`에서 대칭적으로 처리합니다.
- 매 프레임 `Find`, 반복 `GetComponent`, 문자열 조회와 불필요한 할당을 하지 않습니다.
- 2D 기능은 2D 물리 API, 입력은 Input System, 렌더링은 URP 2D 호환 구현을 사용합니다.
- Editor 전용 코드는 `Editor/`, 테스트 코드는 필요한 경우 `Tests/` 영역에 분리합니다.

## Editor와 에셋

- Unity MCP를 사용할 수 있으면 Editor 상태와 대상 씬·GameObject·컴포넌트를 먼저 확인합니다.
- 씬, Prefab, ScriptableObject는 가능하면 Unity Editor/MCP로 수정하고 작업 후 저장과 시각 결과를 확인합니다.
- 에셋 이동·삭제 시 `.meta`와 GUID를 보존하며 직렬화 참조를 손상시키지 않습니다.
- `Library/`, `Temp/`, `Logs/`, `UserSettings/`, `obj/`, `.csproj`, `.sln`은 수정·관리하지 않습니다.
- Unity 및 패키지 버전은 요청 없이 변경하지 않습니다.

## 검증과 완료 보고

- C# 변경 후 컴파일 완료를 기다리고 Console 컴파일 오류가 0건인지 확인합니다.
- 관련성이 높은 최소 테스트부터 실행하고, 씬·Prefab·UI 변경은 Play Mode와 화면 결과를 확인합니다.
- 완료 보고에는 변경 대상, 실행한 검증, 미검증 항목과 남은 위험을 간단히 적습니다.
- 실행하지 않은 테스트나 확인하지 않은 동작을 성공했다고 보고하지 않습니다.

## graphify

- Graphify 실행 루트와 출력 위치는 `Hyper_Project/`와 `graphify-out/`입니다.
- 코드베이스 질문은 `graphify-out/graph.json`이 있으면 먼저 `graphify query "<질문>"`으로 확인합니다.
- 관계와 개념은 각각 `graphify path "<A>" "<B>"`, `graphify explain "<개념>"`을 우선 사용합니다.
- 코드 변경 후 `Hyper_Project/`에서 `graphify update .`을 실행합니다.
- `.graphifyignore`를 준수하며 `graphify-out/`은 Git 관리 대상에 포함하지 않습니다.
